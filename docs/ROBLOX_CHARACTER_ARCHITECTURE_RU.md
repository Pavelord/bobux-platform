## RobloxParity и BobuxExtensions

Профиль RobloxParity включает только подтверждённое поведение классического Humanoid. CCL имеет отдельный профиль и собственную матрицу; результаты ControllerPartSensor сами по себе не доказывают поведение классического Humanoid. Дополнительные механики Bobux не включаются в импортируемой карте автоматически.

Существующие coyote time, jump buffer, sensor reach, spring/friction и ограничение падения пока не подтверждены новой матрицей: их источник — ENGINE_APPROXIMATION или BOBUX_EXTENSION. Их нельзя удалить вслепую до измерений и регрессии. Ledge-hang, физический захват кистями и перенос наверх не подменяют измеренное Climbing. Новый выход через верх должен быть непрерывным физическим движением, если эталон не показывает количественно подтверждённого скачка позиции.

Соответствие старого registry новым меткам: `documented` → ROBLOX_DOC, `measured` → ROBLOX_MEASURED, `engineering_approximation`/`TODO_MEASURE` → ENGINE_APPROXIMATION (последнее означает ещё не проверено), `custom` → BOBUX_EXTENSION. STANDARD_SCRIPT — отдельно извлечённая константа публичного скрипта, не доказательство физики. Источник прикрепляется к каждому важному числу.

## EnumItem: безопасная граница VM

Нужны канонические неизменяемые EnumType/EnumItem с Name, Value, EnumType, typeof, tostring, равенством и GetEnumItems. Значения берутся из официального schema и живой Studio, неизвестные значения не придумываются. Общий registry нормализует присваивания для GDScript: `value(input, expected_domain)`. Не следует ранжировать AnimationPriority по Value: Core имеет отдельный порядок.

Первый этап содержит два явных представления: существующие NumericEnums и RobloxParity EnumItem. Одним и тем же namespace невозможно одновременно воспроизвести native `EnumItem ~= number` и сохранить авторский `GetState()==3`. Поэтому переход определяется corpus-аудитом и функциональной регрессией; наличие нового класса не объявляется выполнением A3.

Профиль хранится в конкретном runtime/VM, не в общем BobuxInstance, Node или глобальном current_profile. Wrapper и BobuxEvent разделяются несколькими VM; их изменение не должно переключать соседний Script/LocalScript. Перевод getter/method return и аргументов события выполняется у VM границы. EnumItem в RemoteEvent сериализуется доменом и именем/значением, а не нативным object ID. Некорректный домен отклоняется. Numeric metadata внутри Godot может сохраняться.

## Сеть и жизненный цикл

Новые поля проверяются по комнате, владельцу, поколению DataModel и жизни персонажа. Смещение серверной комнаты не является позой Workspace клиента. Положение/скорость/Climbing от клиента не принимаются как доказательство допустимой физики: геометрия и состояние требуют ограниченных по нагрузке проверок.

Текущий токен защищает замену модели; повторное использование Node после смерти — отдельный незакрытый пункт F4. Предпочтительно новое поколение Humanoid с очисткой старых связей, либо отдельный безопасный life ID. Это нельзя объявлять решённым только по совпадению сетевого actor token.

Существующие RPC и текущий опубликованный сервер не изменяются этой подготовкой. Перед новым протоколом обязательны обе комбинации старый/новый клиент/сервер. Если они не поддерживаются, нужен явный version negotiation и порядок обновления; успешный localhost с одинаковыми исходниками не доказывает обратную совместимость.

## Измерения, допуски и результаты

Для новых datasets параметры матрицы, split и допуски сохраняются до запуска и до подбора. Train и holdout имеют стабильные ID; подбор не читает holdout. Сохраняются simulation/wall/render time, actual callback dt, Studio version, controller profile, rig/settings и SHA-256. Старые 35 сценариев считаются исторической калибровкой, не новым независимым holdout.

Точные API/enum/порядок событий требуют точного совпадения. Для движения задаются отдельные расстояния, скорости, углы и временные критерии. Landed дополнительно проверяется числом физических шагов и распределением при ≥10 падениях; старый валидатор с пятью FAIL не переписывается ради нового результата. Неизмеримое — NOT_OBSERVABLE; отсутствие данных — BLOCKED; завершённая отрицательная геометрическая проба не является провалом запуска.

Тяжёлые Studio и Godot тесты идут последовательно. Исходники стандартных Roblox скриптов читаются только в официальной Studio; сохраняются inventory и агрегаты/константы/вызовы, не сами scripts или оригинальные анимационные ключи/ассеты. Видеодоказательства снимаются с собственного native стенда.

## Коммиты и отчёт

Каждая проверенная подзадача получает отдельный краткий отчёт и небольшой коммит. Новые документы/стенды можно фиксировать отдельно. Для файлов с предшествующими незакоммиченными изменениями требуется отделить новую правку от исходного snapshot; нельзя включать весь старый diff в коммит фазы. Существующее содержимое и index пользователя сохраняются.

Общий статус COMPLETE запрещён при незакрытых критических FAIL/BLOCKED или неизвестном покрытии. Матрица отдельно показывает подтверждённое поведение, частичную поддержку, отсутствующие API, extensions, ограничения производительности и сетевых версий.
