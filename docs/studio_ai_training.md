# Как улучшать и обучать Bobux AI

Сейчас Studio использует внешнюю модель через серверный API. В коде есть адаптеры Yandex и Gemini; провайдер выбирается серверной настройкой BOBUX_AI_PROVIDER. Изменение подсказки и добавление заготовок не обучает её веса. Сервер проверяет JSON-действия, клиент применяет их к карте. Дообучение не добавляет отсутствующие функции Lua-движка.

## С чего начать помощнику проекта

Сначала нужен человек, который проверяет примеры, а не дорогой сервер. Можно начать с 30 задач, выполненных вручную: 10 предметов, 10 изменений готовой карты и 10 GUI/скриптов. Для каждой задачи сохранить исходную карту, запрос, правильные действия, итоговую карту и результат проверки в Play и обычном режиме. Затем расширять набор до нескольких сотен разнообразных задач. Это ориентир для первого эксперимента, не гарантия качества.

Пример задания: «У существующего меча изменить урон с 10 на 25, остальные настройки сохранить». Проверка должна убедиться, что это тот же предмет, новый меч не создан, удар снимает 25 здоровья и карта сохраняется после изменения. Один только красивый текст ответа за правильное выполнение не считается.

Знания о доступных командах Studio и готовых предметах лучше подставлять в запрос из актуальной документации и каталога (поиск примеров, или RAG). Модель получает состояние карты, находит существующие объекты по ID и предлагает действия. После выполнения ей можно вернуть ошибку и попросить исправление в копии карты с ограниченным числом попыток. Это отдельная доработка агента, её нельзя заменить загрузкой файла для обучения.

## Практический порядок

1. Собрать 200–500 качественных задач: оружие, NPC, GUI, изменение существующего скрипта, перестройка участка карты, подбор моделей. Для каждой сохранить запрос, сокращённое состояние сцены с ID объектов, правильные действия редактора и Lua-код.
2. Каждый пример выполнить в копии карты. Проверить результат и ошибки Lua, а не только корректный JSON. Записать критерии: пистолет стреляет, GUI вызывает событие, NPC получает урон, изменение не удаляет соседние объекты.
3. Сначала подключить библиотеку проверенных примеров и документацию поддерживаемых API к запросу модели. Это дешевле обучения и легко обновляется с движком.
4. Отделить контрольные задачи до обучения. Разделять по картам и семействам задач, чтобы почти одинаковые примеры не оказались и в обучении, и в проверке. Например, 80% обучение, 10% подбор параметров, 10% окончательная проверка.
5. Сравнивать версии по успешному выполнению задач в Studio и обычном режиме, времени и стоимости. Ошибки не добавлять как правильные ответы. Длинные цепочки отдельно проверять на отмену и сохранение карты.

Пример записи собственного исходного датасета (перед загрузкой преобразовать в формат выбранного провайдера):

```json
{
  "request": "Измени урон существующего пистолета на 20",
  "scene_context": {"selected_id": "tool_42", "scripts": []},
  "expected_actions": [],
  "checks": ["Существующий Tool сохранён", "Попадание снимает 20 здоровья"],
  "engine_version": "зафиксированный коммит",
  "result": "passed"
}
```

`expected_actions` должен содержать реальные, проверенные действия текущего протокола Studio, а не вымышленные команды. Схема и системная инструкция находятся в `services/bobux_api/server.js`.

## Внешняя модель или свой сервер

- **Внешний сервис:** использовать дообучение, которое поддерживает выбранный провайдер. На момент проверки документации 21 сентября 2026 года Yandex описывает LoRA для YandexGPT Lite в Preview; это не означает, что можно обучить любую модель из каталога. Создать отдельный проект обучения, загрузить датасет нужного формата, запустить обучение и получить ID. Проверить модель на отложенных задачах. Для Yandex затем задать её modelUri через серверный BOBUX_AI_MODEL в тестовом окружении, сохранив тот же системный промпт. Только после сравнения качества переключать продакшен. Документация: https://aistudio.yandex.ru/en/docs/ai-studio/concepts/tuning/
- **Своя модель:** выбрать открытую модель для кода с подходящей лицензией, обучать адаптер LoRA/SFT на GPU через TRL, затем обслуживать запросы отдельным inference-сервером. Документация: https://huggingface.co/docs/trl/sft_trainer и https://docs.vllm.ai/en/latest/serving/online_serving/openai_compatible_server/
- Нынешний игровой VPS с 2 ГБ RAM не подходит для полноценного обучения и обслуживания такой модели. GPU-сервис лучше отделить от игровых комнат, чтобы генерация не тормозила игроков. Конкретные GPU и стоимость выбираются после выбора модели и теста нагрузки.
- OpenAI-compatible endpoint vLLM сам по себе не совместим с текущими Yandex/Gemini-адаптерами Bobux. Для него потребуется отдельный серверный адаптер запросов/ответов с теми же проверками действий, таймаутами и ограничениями. Простая замена BOBUX_AI_BASE_URL этого не решает.

## Своя модель: последовательность для разработчика

1. Выбрать базовую открытую модель, разрешающую нужное использование. Сначала оценить её без обучения на тех же задачах Bobux. Не покупать GPU до этого сравнения.
2. Подготовить JSONL с диалогами: системная инструкция текущей Studio, запрос пользователя со сценой и правильный ответ с действиями. Формат conversational поддерживает TRL SFTTrainer. Не подмешивать контрольные карты в обучение.
3. На отдельном GPU обучить LoRA-адаптер через TRL и PEFT. Это небольшая надстройка над исходной моделью. Объём видеопамяти зависит от размера модели, длины контекста, точности и метода обучения; универсального обещания «любой GPU подойдёт» нет.
4. Сохранить базовую модель, адаптер, версии библиотек, параметры и отчёт проверки. Сравнить исходную модель и адаптер: доля реально работающих задач, ошибки Lua, сохранение карты, время ответа.
5. Запустить сервер генерации, например vLLM, в отдельном окружении и подключить его через новый адаптер Bobux API. Ограничить очередь и число запросов. Ключи остаются на сервере.
6. Сначала дать доступ тестерам. Сохранить возможность вернуться к предыдущей модели. Данные игроков не должны автоматически превращаться в обучающий набор без отбора и разрешения.

Официальные руководства: https://huggingface.co/docs/trl/sft_trainer и https://docs.vllm.ai/en/latest/serving/openai_compatible_server/

Игроку, который хочет помогать, достаточно выдать отдельную копию проекта, описание действий и папку датасета. Продакшен-ключи, токены пользователей, пароли и база аккаунтов для обучения не нужны. Перед использованием чужих карт/скриптов в датасете проверить разрешение авторов.

Автоматический запуск платного обучения или покупка GPU в этом обновлении не выполняются.
