# Как улучшать и обучать Bobux AI

Сейчас Studio использует внешнюю модель через серверный API. Изменение подсказки и добавление заготовок не обучает её веса. Сервер проверяет JSON-действия и применяет их к карте. Дообучение не добавляет отсутствующие функции Lua-движка.

## Практический порядок

1. Собрать 200–500 качественных задач: оружие, NPC, GUI, изменение существующего скрипта, перестройка участка карты, подбор моделей. Для каждой сохранить запрос, сокращённое состояние сцены с ID объектов, правильные действия редактора и Lua-код.
2. Каждый пример выполнить в копии карты. Проверить результат и ошибки Lua, а не только корректный JSON. Записать критерии: пистолет стреляет, GUI вызывает событие, NPC получает урон, изменение не удаляет соседние объекты.
3. Сначала подключить библиотеку проверенных примеров и документацию поддерживаемых API к запросу модели. Это дешевле обучения и легко обновляется с движком.
4. Отделить контрольные задачи до обучения. Разделять по картам и семействам задач, чтобы почти одинаковые примеры не оказались и в обучении, и в проверке. Например, 80% обучение, 10% подбор параметров, 10% окончательная проверка.
5. Сравнивать версии по успешному выполнению задач в Studio и обычном режиме, времени и стоимости. Ошибки не добавлять как правильные ответы. Длинные цепочки отдельно проверять на отмену и сохранение карты.

Пример записи собственного исходного датасета (перед загрузкой преобразовать в формат выбранного провайдера):

```json
{
  "request": "Измени урон существующего пистолета на 20",
  "scene_context": {"selected_id": "tool_42", "scripts": []},
  "expected_actions": [],
  "checks": ["Существующий Tool сохранён", "Попадание снимает 20 здоровья"],
  "engine_version": "зафиксированный коммит",
  "result": "passed"
}
```

`expected_actions` должен содержать реальные, проверенные действия текущего протокола Studio, а не вымышленные команды. Схема и системная инструкция находятся в `services/bobux_api/server.js`.

## Внешняя модель или свой сервер

- **Внешний сервис:** использовать дообучение, которое поддерживает выбранный провайдер. Для текущего Yandex AI Studio нужны отдельные права, датасет и обучение модели; затем сервер направляется на её идентификатор. Доступность, лимиты и стоимость проверяются перед запуском: https://aistudio.yandex.ru/en/docs/ai-studio/concepts/tuning/
- **Своя модель:** выбрать открытую модель для кода с подходящей лицензией, обучать адаптер LoRA/SFT на GPU через TRL, затем обслуживать запросы отдельным inference-сервером. Документация: https://huggingface.co/docs/trl/sft_trainer и https://docs.vllm.ai/en/latest/serving/online_serving/openai_compatible_server/
- Нынешний игровой VPS с 2 ГБ RAM не подходит для полноценного обучения и обслуживания такой модели. GPU-сервис лучше отделить от игровых комнат, чтобы генерация не тормозила игроков. Конкретные GPU и стоимость выбираются после выбора модели и теста нагрузки.
- OpenAI-compatible endpoint vLLM сам по себе не совместим с текущим Yandex-протоколом Bobux. Для него потребуется отдельный серверный адаптер запросов/ответов с теми же проверками действий, таймаутами и ограничениями.

Игроку, который хочет помогать, достаточно выдать отдельную копию проекта, описание действий и папку датасета. Продакшен-ключи, токены пользователей, пароли и база аккаунтов для обучения не нужны. Перед использованием чужих карт/скриптов в датасете проверить разрешение авторов.

Автоматический запуск платного обучения или покупка GPU в этом обновлении не выполняются.
