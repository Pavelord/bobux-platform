# Оптимизация Bobux: клиент, Android, Luau и сервер

Дата начала проверки: 9 октября 2026. Этот файл дополняется результатами проверки кандидата и выпуска.

## Границы изменений

Карты и их Luau-исходники не редактируются. Исправления выполняются в загрузчике, адаптерах Roblox API, VM/runtime, репликации и сервере. Возможности скриптов, события кадров и пользовательские механики сохраняются. Полное отсутствие лагов пока не подтверждено.

Тестовый Android-пакет `com.bobux.performance` отделён от установленного `com.bobux.game`. Устройство: Samsung Galaxy A55 SM-A556E, Android 16, Xclipse 530. Проверяется экспорт на release-шаблоне Godot 4.7 с настоящим Luau 0.719, а не Lua 5.4. Локальные сетевые тесты используют изолированные каталоги данных и отдельные порты.

## Что изменено

- Список карт на API получает ограничение размера страницы и метаданные по умолчанию. Полное содержимое карты сохраняется для запроса конкретного ID. `select` на живом сервере уже работал во время проверки; прежняя информация об ошибке 400 не воспроизвелась. Смещение страниц в локальном API до исправления игнорировалось.
- Одновременные загрузки одного ассета объединены в один HTTP-запрос. Разные URL, записывающие в один файл, выполняются последовательно и не получают содержимое другого URL.
- Создание карты распределено по кадрам с бюджетом 3 мс. Повторные примитивы, материалы, UV-варианты и одинаковый код шейдеров используют общие ресурсы. Изменение цвета отдельной детали сохраняет независимость других деталей и повторно использует её собственный материал.
- Сцена игры и опубликованные меши предварительно загружаются. Графический клиент использует три фоновых загрузчика и ограниченный кэш. Оценка кэша 48 МБ относится к размеру файлов, а не гарантирует такой же объём RAM. Для headless-сервера создание мешей оставлено на главном потоке с бюджетом по кадрам: параллельный путь вызывал ошибки RID в dummy renderer.
- Во время построения карты Android временно приостанавливает отрисовку частично загруженного 3D-мира за экраном загрузки. Скрипты, физика и интерфейс продолжают работать; после завершения и при отмене отрисовка восстанавливается.
- Подготовка Luau-исходников переписана без квадратичных замен и вынесена в фон. Результат преобразования проверяется на побайтовое совпадение со старым алгоритмом. Скомпилированные контексты очищаются с учётом времени жизни native callbacks.
- Стили GUI обновляются при изменениях, а не пересоздаются полностью каждый кадр. Текст, видимость, размеры родителя, декораторы и layout остаются живыми.
- Поиск встроенных свойств использует кэш схемы native-класса, но не кэш значений. Динамические свойства GDScript, метаданные и поля с `/` сохраняют прежний путь поиска.
- Для CFrame и других несравнивавшихся ранее значений не создаётся ненужный объект предыдущего значения. Каждая запись и каждое событие изменения продолжают исполняться.
- Все готовые обработчики Stepped, Heartbeat и RenderStepped доставляются с исходным delta. Прежний лимит 8 обработчиков/1,5 мс мог терять события. Приостановленные anchored physics adapters перестают получать пустые вызовы physics_process.
- Планировщик task использует справедливый курсор: короткий бюджет кадра больше не оставляет задачи в конце очереди без исполнения. Watchdog считает CPU Luau, исключая время ожидания ОС и выполнения Godot API; вложенные Lua callbacks снова учитываются. Отдельная бесконечная task не отравляет бюджет родительской coroutine. Защита от бесконечных скриптов сохранена.
- TweenService интерполирует UDim2, GUI getter возвращает UDim2, свойства света обновляют native-свет, Cylinder создаёт цилиндр. Вложенные и приостанавливаемые require в одной VM сохранены. Luau собран для всех семи используемых комбинаций платформы и архитектуры; debug Android и Windows 32-bit больше не выбирают старую Lua 5.4.
- Сервер сериализует общие и приватные представления комнаты один раз на представление, а не на каждого получателя. WebSocket-очередь учитывает фактическое заполнение буфера и сохраняет неотправленные chunks: прежняя отправка восьми chunks по 12 КБ за кадр переполняла буфер 64 КБ во время NDS.
- Spawn и movement аватаров фильтруются по комнате. Сервер получает авторитетное состояние движения владельца; другие комнаты не получают его avatar spawn/movement. Приватный GUI доставляется только владельцу.
- Схема spawn содержит новый Synchronizer. Настоящий тест со старым клиентом выявил ERR_INVALID_DATA при каждом spawn; обновлённый клиент проходит spawn/movement/hide/respawn без этих ошибок. Версия протокола client/server повышена до `vps-ws-2026-10-10-1`. Старые приложения получают существующее сообщение о необходимости обновления до создания комнаты/аватара. Новый клиент и сервер выпускаются вместе.
- Общий HUD больше не рисует широкую верхнюю полосу. Кнопки Bobux, чата и инвентаря размещены в компактных тёмных элементах слева; меню открывается значком Bobux, отдельная кнопка с тремя полосами удалена. HP справа — простая зелёная шкала без текста и карточки. Отступы учитывают safe area телефона. Авторские GUI режимов не изменены.
- Удалены активные Supabase autoload и старый клиент. Файлы находятся в локальном исключённом из экспорта архиве `.codex-tmp/retired-supabase`; старый формат файла сессии читается только для миграции существующих пользователей. Подключений к Supabase нет.

## Изученные режимы и ограничения архитектуры

**Бобукс парк с бобукс крутом:** 1392 сохранённых блока, около 0,88 МБ JSON и 15 МБ ассетов. Основной сценарий BobuxKrutStory — 4260 строк. Он использует один контроллер Heartbeat, много CFrame-записей, GUI и динамически создаваемых объектов. Комментарии сценария прямо описывают обход прежнего ограничения доставки callbacks. Дорогой поиск отсутствующего свойства TextTransparency и полное обновление стилей создавали большой расход CPU. Начальная поездка длится примерно 14 секунд; измерения теперь выполняются после неё. Короткая старая разминка могла измерять меню или вступление, поэтому старые FPS нельзя безоговорочно сравнивать с полным игровым процессом.

**Долина Семи Ветров:** 4269 блоков, около 1,31 МБ JSON, 653 ассета и 41 МБ файлов. Много повторяющихся программ шейдеров в отдельных файлах мешей. Животные в опубликованном сценарии обновляются с частотой 15 Гц; отдельной визуальной интерполяции между обновлениями в сценарии нет. Автоматическое вращение камеры диагностикой выключено по умолчанию. Режим не переписывается ради более плавной анимации.

**Natural Disaster Survival:** большой JSON включает библиотеки шаблонов в Lighting; в старом снимке около 7483 записей и 13 МБ JSON. Проверяется актуальная опубликованная версия с ID `z9ovqynlv860sgw_narural disaster survival - bobux edition`, поскольку на сервере есть несколько похожих режимов. Массовые создания, удаления и изменения деталей нагружают одновременно scheduler, физику и репликацию. Требуются проверки полных циклов бедствий и нескольких клиентов, а не только входа на пустой сервер.

**Нормальный лифт:** ID `evd29np4936q499_normalnyi_lift`, три исходника: ShopItems (60 строк), ElevatorServer (2173), ElevatorClient (288), 38 вариантов этажей и 38 способностей. Исправлены интерполяция UDim2, GUI getter, свет, Cylinder и голодание task. Первый запуск неизменённого ElevatorServer выявил ложное срабатывание watchdog на дорогом Godot API; после перехода на CPU Luau оригинальные server/client скрипты прошли проверку: этаж и GUI созданы, 319 узлов, failed=0. Windows и официальный Linux Godot 4.7 отдельно проверяют долгий native вызов и реальные бесконечные Lua циклы.

## Дальнейшие требования к движку

Нужны чёткие границы модулей для загрузки, Roblox API, GUI, планировщика и репликации вместо дальнейшего роста main/lobby/studio/lua_script_engine. Разбиение файлов само по себе не является оптимизацией: зависимости должны загружаться по необходимости.

Для серверной масштабируемости нужны регистрация изменённых объектов, компактные статические версии карт и доставка изменений по области интереса. Полный обход дерева каждой комнаты и повторная сериализация неизменных объектов плохо масштабируются. Для GPU нужен проверенный механизм объединения неподвижной геометрии, который сохраняет Instance identity, коллизии, прозрачность, тени, Clone и все способы перемещения. Экспериментальный механизм сейчас включается диагностическим флагом и должен пройти визуальную проверку перед включением в выпуск.

Существующая сетка room origins имеет коррелированные hash для x/z и большие координаты вплоть до 630000. Это создаёт риск совпадения комнат и потери точности float. Следующий этап требует согласованной версии client/server protocol и изоляции миров либо компактного размещения комнат; замена формулы только на сервере нарушила бы координаты старых клиентов. API также пока получает PocketBase rows до применения страницы: требуется перенос фильтра и пагинации в запрос к базе.

## Проверки и выпуск

Регрессионные проверки охватывают совместное использование ресурсов и независимость материалов, гонки загрузки ассетов, физику, GUI-стили, все события кадров, подготовку исходников, остановку runtime, динамические свойства, Luau authoring, parity Roblox API и API-сервера. Отдельно добавлены тесты справедливости очереди задач и контрактов лифта.

Полный сетевой NDS regression: реальный Tsunami (1302 детали), первый и поздний клиент, все три процесса завершились успешно, failed=0, SCRIPT ERROR/ошибок отправки нет. Очередь достигла 314 chunks и затем разгрузилась. На локальном сервере p95 кадра 23,593 мс; единичный максимум 816,498 мс при создании/клонировании/снимке мира остаётся ограничением. Четыре клиента в двух комнатах прошли spawn/movement/privacy проверку, включая переход из A2/B1 в A3.

Прототип static batching прошёл mutation/Clone/PivotTo/MoveTo/BulkMoveTo и графический тест: 128 → 11 draw calls, среднее отличие RGB 0,0003236. Он пока выключен по умолчанию; измеряется отдельно на настоящих режимах Android. Финальная упаковка проверяет размер, архитектуру и SHA-256 Luau во всех пакетах и неизменность семи native файлов во время экспорта.

## Финальный кандидат build 54 (10 октября)

Все четыре опубликованных режима проверены с выключенным experimental static batching. На Samsung A55 использован release-шаблон Godot и production Luau ARM64, отдельный пакет диагностики с финальным зелёным HP/HUD. Измерения по 15 секунд после готовности мира и окончания вступления; кэш уже прогрет. На PC использован Godot 4.7 с графикой и native Windows debug x86_64, по 10 секунд. Это не замена полноценному тесту поставляемого Windows x86_32 пакета: для него пройдены проверки упаковки/native smoke, а release-шаблон запрещает подмену главной сцены через командную строку.

| Парк | 18,480 с | 22,95 / 51,746 мс | 8,535 с | 117,89 / 11,564 мс |

Во всех восьми прогонах runtime failed=0, отчёты не содержат failures. Android logcat не содержит ошибок скриптов/транспорта. На PC во время игровых выборок нет кадров длиннее 50 мс; после завершения процесса остаётся предупреждение Godot о двух ObjectDB instances. Скорость загрузки зависит от ассетов и сети; результаты не гарантируют тот же FPS на других устройствах и стадиях игры. Парк и долина на телефоне пока не достигают стабильных 60 FPS.

Доказательства: `.codex-tmp/performance/android-green54.json`, `.codex-tmp/performance-pc54/Godot/app_userdata/Bobux/performance/windows64-candidate54.json`, `.codex-tmp/performance/compact-hud-green.log`. Проверка HUD подтверждает высоту HP 8 px, изменение значения 72/120, отсутствие цифр/карточки/кнопки с тремя полосами, меню через Bobux и скрытый дублирующий текстовый Inventory.

Протокол проверен реальным WebSocket handshake на изолированном порту 18148. Старый `vps-ws-2026-10-06-1` получает русское требование обновления до отключения, не создаёт комнату и не загружает карту. Новый `vps-ws-2026-10-10-1` завершает request/confirm/complete/ready и входит в Classic. Все три процесса завершились с кодом 0, без ERROR; тест добавлен в CI. Логи: `.codex-tmp/performance/protocol-gate/`.

Снимок данных четырёх режимов перед публикацией сохранён в `.codex-tmp/performance/release54-mode-hashes.json`: проверяются полные JSON и хеши всех уникальных Source/code/original_source. В релиз входят Windows/Linux 0.1.49 build 54, Android 0.1.49-mobile build 54 и launcher 0.1.19 build 21. Публикация выполняется с staged import/Luau/API тестами и откатом runtime/API/манифестов; результат live smoke и путь резервной копии будут добавлены после переключения сервера.
