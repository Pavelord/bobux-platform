# Профиль в обновлении 55

Дата присоединения берётся из существующей записи авторизации PocketBase. Для старой записи без доступного аккаунта используется дата создания профиля, если она есть. Текущая дата устройства не подставляется вместо регистрации. В интерфейсе показывается «—», если достоверной даты нет.

Описание редактируется только владельцем через `update_profile_about`. Сервер определяет владельца по токену, игнорирует присланные `user_id`, дату и счётчики. До 1000 символов Unicode сохраняются как обычный текст в новой таблице `profile_about` существующего `social.sqlite`. Чужой профиль доступен для просмотра; его описание изменить нельзя.

`profile_visits` хранит уникальные идентификаторы посещённых режимов. Посещения учитываются с обновления 55 после готовности мира и появления собственного персонажа; запрос выполняется в фоне и не задерживает игру. Неудачные подключения, диагностические замеры и выделенный сервер не регистрируют новое посещение. Старый `UserSession.recent_games` содержит также попытки подключения, поэтому в счётчик успешных посещений не переносится. Полный архив успешных посещений старых версий недоступен. «Modes visited» показывает число разных режимов, успешно посещённых с этого обновления; это уточнение присутствует в подсказке счётчика.

При открытии чужого профиля его снимок применяется до показа вкладки. Поколение запроса проверяется после каждого асинхронного этапа; поздний ответ другого профиля не меняет выбранного игрока. Подтверждённое сохранение описания также отменяет старый запрос профиля, чтобы устаревший GET не возвращал прежний текст. Снимки профилей кешируются отдельно по идентификатору аккаунта.

About содержит описание, статистику и Currently Wearing. Дублирующий My Games убран; игры автора остаются в Creations и запрашиваются при открытии этой секции. Карточки Creations адаптируются к доступной ширине: три колонки на широком экране и одна на телефоне. Надетые аксессуары, рубашка и штаны отображаются отдельными аккуратными карточками с реальным превью модели; Limited сохраняет зелёную плашку и белую надпись. Дубликаты одежды не добавляются. Повторное обновление статистики не пересоздаёт неизменившиеся превью.

Персонажа можно вращать мышью, пальцем и кнопками по 44 px. Эмулируемая мышь после касания не поворачивает модель второй раз. На узких экранах те же секции располагаются вертикально. Проверка обнаружила и исправила перенос минимальной ширины десктопного содержимого через `ScrollContainer.SCROLL_MODE_DISABLED`: используется скрытая горизонтальная полоса с адаптивными колонками, рассчитанными по доступной ширине экрана.

Сервер больше не обрезает публичные списки надетых аксессуаров до 6 моделей или 48 идентификаторов. Существующая облегчённая передача ресурсов и ограничения размера тела запроса сохраняются. Карты, исходные Luau-скрипты, инвентарь и сессии этим изменением не переписываются.

- `tools/validate_profile_update.gd`: 45 проверок, PASS. Собственный профиль → Alice → Bob, ответы в другом порядке, сохранение во время переключения, поздний GET после сохранения, реальные даты, запрет переноса старых попыток в статистику успешных посещений, мышь/касание, Limited, превью одежды, границы содержимого и экрана при 360/540 px, компиляция успешного spawn-hook. Три заполненные карточки Creations проверены при 360/540/1440 px, включая количество колонок и отсутствие горизонтального переполнения.
- `tools/validate_cached_lobby_shell.gd`: PASS, только ожидаемые предупреждения тестового сетевого таймаута и повторного подключения.
- Все 13 тестовых файлов API: PASS; новый `profile_details.test.mjs` проверяет авторизацию, подмену владельца, дату регистрации, Unicode, уникальные посещения, недоступные режимы и сохранение после повторного открытия SQLite.

Найденный существующий дефект `_create_profile_game_card` исправлен точечно: кнопка Studio создаётся только при наличии локального `folder`. Три orphan Button и связанные TextParagraph/CanvasItem/Image/ImageTexture/RID предупреждения после этого исчезли. Headless-завершение чистое. В графическом завершении остаются только два RefCounted с reference count 0; они отдельно зафиксированы в combined stdout/stderr. Это не подтверждение отсутствия утечек во всех сценариях игры.
