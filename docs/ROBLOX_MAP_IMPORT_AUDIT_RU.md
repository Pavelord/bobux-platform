# Аудит импорта Roblox-карт

Дата проверки: 3 октября 2026 г. Движок: Godot 4.7 stable, Windows, 16 ГБ RAM.

## Вывод

Конвертер распознал все 21 исходный файл. Все 14 215 объектов `Script`, `LocalScript` и `ModuleScript` прошли проверку синтаксиса Luau; в манифестах не потеряно ни одной части из `ServerStorage` и родственных хранилищ. Полную сборку сцены удалось проверить на 20 картах: в отчётах нет потерянных ссылок, неверных родителей, пустой геометрии или ошибок самого импортёра.

Это подтверждает целостность загрузки сцены, но не работу самой игры. На четырёх картах выполнен ограниченный playtest: на двух ошибки Lua не возникли, на старом Doomspire упали 24 из 31 стартовавшего скрипта, на Nikilis MM2 — 8 из 17. Причины — неподдержанные Roblox API, загрузка внешних ModuleScript по числовому asset ID, отличия окружений модулей и несовпадение типов. Наиболее крупная карта, ACF Vanguard, не прошла построение сцены: её JSON потребовал больше памяти, чем безопасно оставалось в тестовой среде.

Таким образом, проблема «карта загружается, но не работает» находится главным образом после чтения файла: импортёр строит дерево объектов, но конвертер теряет часть значений, визуальные и физические классы поддержаны не полностью, а Lua-мост пока реализует лишь часть Roblox API.

## Что именно проверено

- Найдены все 21 указанных файла в `C:\Users\Pavel\Downloads`. Повторные файлы `2017 - Lego's Plane Wars (1).rbxl` и `2017 - Lego's Plane Wars.rbxl` имеют одинаковый SHA-256 и одинаковые результаты. Оба файла с расширением `.rbxl` внутри оказались XML; формат был распознан автоматически.
- Каждый исходник разобран `rbxl_converter.parse_rbxl` и преобразован в тот же строгий JSON-представитель, который использует приложение. На этом этапе сетевую загрузку Roblox-ассетов отключили, чтобы не смешивать ошибки карты с доступностью удалённых или закрытых asset ID.
- Для каждой карты построен манифест Roblox Runtime и вызван `LuaScriptEngine.validate_script_source` для каждого скрипта. Это проверка грамматики/компиляции, а не запуск.
- Для 20 карт выполнены `RbxlRuntimeImporter.import_json_async()` и `LuaScriptEngine.install_roblox_manifest_async()`, затем сверены исходные ссылки и фактические родители. ACF прошла разбор и проверку всех скриптов, но её полное построение сцены было остановлено защитным монитором памяти.

- Отдельно выполнен чистый запуск редактора Godot с `--headless --editor --quit`.

Проверялся живой импорт Place Editor, используемый приложением при загрузке карты. Отдельный путь Godot `EditorImportPlugin`, который создаёт импортированный `PackedScene` в файловой системе редактора, в этот прогон не входил. Отчёт об ассетах отражает локальный кэш: удалённые asset ID, авторизация Roblox и реальный сетевой загрузчик здесь не проверялись.

## Подтверждённые проблемы

### 1. Конвертер меняет значения данных

`sanitize_for_strict_json()` заменяет `NaN`, `+Inf` и `-Inf` на `0.0`, чтобы JSON прошёл строгий парсер Godot. В этих картах так изменены 81 424 числовых поля. Больше всего таких значений в Normal Elevator (47 043), Nikilis MM2 (19 119), Build a Boat (10 982) и Steal a Brainrot (3 976). Среди имён затронутых свойств в предупреждениях есть `MaxDistance`, `MaxAngularVelocity`, `UnscaledCofm`, `UnscaledVolInertiaDiags`, `UnscaledVolInertiaOffDiags` и `UnscaledVolume`.

Для `MaxDistance` бесконечность обычно означает отсутствие конечного предела. После замены на ноль такая проверка/дистанция может стать нулевой. Для физических величин ноль может изменить массу, инерцию и движение. Это тихая порча данных: отчёт сцены продолжает показывать `errors=0`.

**Исправление:** передавать не-конечные числа как типизированный маркер (`+Inf`, `-Inf`, `NaN`) или tagged-value в промежуточном формате. На стороне Godot восстанавливать значение только там, где оно допустимо; для запрещённых свойств применять документированный Roblox default и записывать предупреждение с `ref`, классом, свойством и исходным значением. Не приводить все такие случаи к нулю.

### 2. `Tags` хешируются вместо сохранения

Конвертер компактирует поля из списка `COMPACT_STRING_PROPERTIES`, в который включён `Tags`. Всего создан 1 016 533 marker-значения; 1 011 708 имели нулевую длину. В 4 825 непустых полях `Tags` исходный текст заменён на строку вида `__bobux_blob__:Tags:<длина>:<hash>`. В Lua-мосте `GetTags()` читает `Tags` как строку, поэтому видит marker вместо реальных тегов; `GetTagged()` не находит экземпляры по исходному тегу.

**Исправление:** считать `Tags` текстовым полем и не помещать его в общий compact-list. Упаковывать только фактические большие бинарные буферы. Для прочих бинарных данных сохранять payload в sidecar blob-файле по хешу и передавать в JSON его ссылку. Добавить сверку `GetTags()`/`GetTagged()` на импортированной карте.

### 3. Промежуточный JSON непропорционально велик

Суммарный сгенерированный JSON занимает около 1,60 ГБ. ACF — 976,3 МБ при исходном файле 14,63 МБ (увеличение в 66,8 раза); Build a Boat — 167,3 МБ при 5,29 МБ; Elevator — 103,3 МБ при 3,77 МБ; Nikilis MM2 — 95,6 МБ при 2,66 МБ. Большая часть увеличения — словари/строки JSON, повторённые свойства, исходники скриптов и данные экземпляров.

Защищённая попытка импортировать ACF в этой среде начала разбирать JSON, но не дошла до сообщения `Imported ...`: свободная память упала примерно с 7,2 ГиБ до 1,22 ГиБ за 11 секунд. Процесс был остановлен при заданном пороге 1,5 ГиБ. До этого все 3 601 скрипт ACF прошли compile-only проверку; полный импорт сцены для этой карты **не подтверждён**. Ранее манифестный проход ACF достигал примерно 8,2 ГБ working set.

**Исправление:** заменить раздувающийся JSON на компактный формат с таблицей экземпляров/свойств и отдельным blob-хранилищем; дедуплицировать одинаковые source и бинарные данные по хешу; читать/создавать манифест потоково или пакетами. Проверять оценку памяти до выделения полного дерева, показывать ошибку с размером/числом экземпляров и давать безопасную отмену. Для крупнейших карт обязательны тесты на машине с ограниченной RAM.

### 4. Импорт создаёт сцену быстрее, чем игру

По 20 картам суммарно импортировано 289 383 исходных part-экземпляра; часть находится в хранилищах, поэтому она не должна отображаться в `Workspace`. При этом 5 118 runtime-классов оказались неподдержанными импортёром, а ещё 14 567 объектов preview оставлены только в metadata, чтобы уменьшить нагрузку редактора.

В числе пропущенных классов: `Bone` — 2 673, `SurfaceAppearance` — 372, `Beam` — 315, `BodyPosition` — 197, `CharacterMesh` — 180, `BodyGyro` — 140, `RopeConstraint` — 128, `BodyVelocity` — 94, `BodyAngularVelocity` — 84. Поэтому у Brainrot особенно страдают скелетная деформация, PBR-вид и лучевые эффекты; у Epic Minigames — legacy BodyMover-физика; у Build a Boat — RopeConstraint. Объект может присутствовать в манифесте и Explorer, но не давать Roblox-поведения.

Часть сеток заменена геометрией-заглушкой из-за отсутствующего локального кэша: 81 у Brainrot, 30 у Be Crushed, 4 у Escape Facility и 2 у Nikilis MM2. Кэшированные меши применяются точно; CSG в некоторых картах сохраняет AssetId, но получает редактируемую fallback-геометрию. Terrain импортируется как voxel `GridMap` preview, что не обещает физическую/редакторскую эквивалентность Roblox Terrain.

**Исправление:** вести таблицу поддержки по Roblox-классам и отражать три состояния: «перенесён и работает», «сохранён только для чтения» и «заменён заглушкой». Приоритетно реализовать `BodyPosition/BodyVelocity/BodyGyro/BodyForce/BodyAngularVelocity`, rope/rod и современные constraints, `Bone`/`Motor6D`, `SurfaceAppearance`, `Beam`/`Trail`, аксессуары и `CharacterMesh`. Для каждой fallback-модели показывать имя, исходный AssetId и причину; не считать её успешной точной геометрией.

### 5. Lua компилируется, но Roblox-среда отсутствует частично

`validate_script_source()` проверяет только загрузку кода в LuaAPI. Она не вызывает `require`, не создаёт игрока и персонажа, не запускает события и не подтверждает доступность сервисов. Playtest показал:

| Карта | Запущено | Упало | Завершилось | Осталось активно | Наблюдение |
|---|---:|---:|---:|---:|---|
| 2011 - Natural disasters survival | 10 | 0 | 8 | 2 | Lua-ошибок нет; headless dummy renderer дважды сообщил `Parameter "material" is null` при завершении. |
| Rocket Arena | 14 | 0 | 13 | 1 | В логе загрузились Leaderboard, Jet Boots и rocket script. |
| Doomspire Brickbattle (без префикса 2017) | 31 | 24 | 4 | 3 | Ошибки в группах `require(assetId)`, `ContentProvider:IsLoaded`, `RemoteEvent.OnServerEvent` и один `nil.new`. |
| Nikilis - Murder Mystery 2 | 17 | 8 | 6 | 3 | Не хватает API/среды модулей, неверный тип UserId, обращения к недостающим узлам/сигналам. |

Подтверждённые точки несовместимости:

- Doomspire запрашивает ModuleScript по числовому Roblox asset ID. Текущий `require()` принимает только объект `ModuleScript` и сообщает `require expects a ModuleScript instance; asset-ID require is unavailable.` В карте есть ошибки, в частности, у `PlayerControl`, `PurchaseControl`, `BrickBattleChatTags`, `Blocks/HD Admin/Settings/Loader` и `Blocks/Lobby/Script`.
- Многие скрипты вызывают `ContentProvider:IsLoaded`; такого метода в compatibility service нет. Один отсутствующий API валит несколько client scripts.
- Server scripts Doomspire читают `RemoteEvent.OnServerEvent`, но Lua получает `attempt to index userdata with 'OnServerEvent'`. В `BobuxInstance` поле и внутренний `BobuxEvent` объявлены; runtime-результат показывает, что свойство не доходит до Lua userdata в используемом пути. Нужно проверить экспорт GDScript-полей через LuaAPI и принудительно разрешать event-properties по `roblox_class`.
- В Nikilis MM2 `ReplicatedFirst.Loading` вызывает `script.Parent:RemoveDefaultLoadingScreen()`; метод `StarterGui` отсутствует. Надёжная локальная реализация может быть no-op, но она должна существовать и быть явно зарегистрирована.
- Скрипт `Preloader` выполняет `Player.userId < 1`. В тестовой сессии `UserId` приходит строкой; Lua сообщает `attempt to compare string < number`. В совместимом контракте `UserId` должен быть целым числом, включая старый alias `userId`; иначе source должен оборачивать значение в `tonumber()`.
- `Insight: Session Reporting` требует `SupportLibrary`, который обращается к `getfenv(2)` и затем к глобальному `Game:GetService(...)` с заглавной буквы. Текущий Lua-мост предоставляет `game`, но не `getfenv`/`setfenv` и не такой общий environment. Затем модуль пытается отправить внешние события через `HttpService:PostAsync`; HttpService/внешняя сеть в runtime API не предоставлены. Для безопасной локальной игры эти вызовы должны возвращать явный stub-result, а не падать молча.
- `GameScript` MM2 сообщает `attempt to index nil with 'Message'` в цепочке `game.Workspace.Status.Message.Version.Text`. В исходном дереве `Workspace.Status.Message.Version` существует, и аудит ссылок не обнаружил потерь. Значит, нужно дополнительно проверить runtime child resolution/контекст `game.Workspace`: ссылка сохранена, но Lua-цепочка получает `nil`.
- Другие наблюдения MM2 — nil `Position` у скрипта VotePads, `ControlScript` с вызовом отсутствующего метода и `LocalSound` с отсутствующим `Connect`. Это нужно привязать к конкретному объекту/персонажу при исправлении R6 playtest: не считать такие сбои ошибкой компилятора карты.

В `require()` есть ещё два архитектурных ограничения: вложенный `require` может изолироваться «для стабильности runtime», а ModuleScript, который yield-ится при синхронном `require`, завершается ошибкой. Это ломает легальные графы зависимостей, даже если все source-файлы компилируются.

**Исправление:** сделать таблицу Roblox API с версией/состоянием реализации и явными результатами для каждого метода. Реализовать корректную module cache, цепочку `require` и cycle detection по Roblox ref; поддержать `getfenv`/`setfenv` или безопасную модель environment, совместимую с `ImportServices`; добавить безопасные локальные stubs для сервисов, которым нельзя делать реальные HTTP/платёжные запросы. Добавить playtest-диагностику по конкретному `Instance path`, source line, отсутствующей возможности и realm.

### 6. Большие карты всё ещё дорого импортировать

Для завершённых карт время импорта сцены вместе с установкой манифеста составило около 810 секунд в сумме на этом компьютере. Epic Minigames занял 188,8 секунд, Build a Boat — 147,3, Nikilis MM2 — 133,0, Normal Elevator — 83,3, Brainrot — 101,1. В `import_json_async()` создание частей и metadata делится на пакеты по кадрам, но большой манифест строится синхронно до этого цикла. JSON также целиком преобразуется в `Dictionary` перед созданием сцены.

**Исправление:** разбивать на этапы «чтение», «манифест», «геометрия», «metadata», «сервисы», «скрипты», показывать прогресс и текущий этап. Построение манифеста тоже пакетировать/yield-ить; индексы ref/parent создавать один раз и переиспользовать; предупреждать и просить выбор только после показа конкретного плана импорта. Для карт выше лимита памяти завершать с понятным сообщением до начала построения частичной сцены.

## Приоритет исправлений

1. **Сохранить данные конвертера:** больше не заменять Inf на 0; оставить непустые `Tags`; добавить проверки сохранения значений при round-trip.
2. **Разблокировать объём:** компактный/потоковый intermediate format, хеш-дедупликация исходников и blobs, ранняя оценка памяти и отменяемый import.
3. **Стабилизировать Roblox Lua bridge:** property/event lookup, числовой `UserId`, обязательные сервисы, ModuleScript graph и полноценные runtime-диагностики.
4. **Перенести игровые классы:** BodyMovers/constraints, R6 joints/accessories, Bone, PBR, Beam/Trail, Terrain и заявляемые fallback-ассеты.
5. **Встроить проверяемый preflight:** parse → instance/ref conservation → compile → API usage scan → bounded playtest → сравнение важной геометрии/сервисов. Import UI должен показывать warnings и блокировать обещание «готово к игре», если есть критические неподдержанные классы или runtime-падения.

## Связанные ошибки Humanoid и `player.gd`

Ранее присланные ошибки `float(Gravity)`, `float(Motion.SafeMargin)` и `Nil` были в конфиге Godot Humanoid, а не в исходниках карт. В рабочем дереве уже добавлены типизированные `HumanoidConfig.float_value()`/`int_value()` и поиск значений по ключу `StringName` либо `String`. Свежая чистая проверка проекта через Godot 4.7 `--headless --editor --quit` завершилась с кодом 0; `player.gd:1372 Expected statement, found Indent` и ошибка конструктора `.tres` в этой проверке не воспроизвелись. Вывод не подтверждает ручной вход во все режимы, но текущий parser scan чистый.

## Воспроизводимые результаты

## Параллельная ветка V2 и внешние референсы

Старая Studio-команда и её путь импорта сохранены. Форматные исправления сначала вносятся и проверяются в отдельном `addons/rbxl_importer_v2/`; результаты полного сравнения этого пути с rbx-dom описаны в [отдельном отчёте](RBXDOM_IMPORTER_COMPARISON_RU.md). В V2 добавлены декодирование `Tags` и `AttributesSerialize`, сохранение `MaterialColorsSerialize` как sidecar, маркировка не-конечных чисел без подмены на ноль, чтение текстовых `Name`/`Source` из BinaryString и 57 375 reflection-совместимых alias-полей для content и GUI-inset свойств с сохранением исходных имён. Эти изменения не означают, что дефекты старого импортёра устранены в рабочем Studio-пути.

Внешние проекты стоит использовать по разным направлениям: [rbx-dom](https://github.com/rojo-rbx/rbx-dom) — для формата и reflection migrations; [rbx-native](https://github.com/chteau/rbx-native) — как дополнительный round-trip/viewer референс после проверки независимости его parser path; [GodotLuau](https://github.com/Pimpoli/GodotLuau) — для сравнительных проверок дерева и Roblox-style runtime API; [RBX-Asset-Extractor](https://github.com/zv8001/RBX-Asset-Extractor) и [Fleasion](https://github.com/fleasion/Fleasion) — для отдельного pipeline локального кэша, мешей и ригов, а не вместо place parser. Сводка совместимости и оговорки по каждому проекту приведены в сравнительном отчёте.
