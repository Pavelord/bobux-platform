# A2: обычный native spawn без собственного Character

Статус на 16 октября 2026: **PARTIAL / R15 ORDINARY OBSERVED**. Фактический R15 измерен в двух профилях default/altered, по **5 независимых Play / joins** в каждом (1–3 train, 4–5 holdout), по 10 native generations на Play. Обе группы R6 и `LoadCharacterWithHumanoidDescriptionAsync` — **NOT_RUN**; весь A2 и Bobux parity не завершены. Доказанные значения, ранние Player defaults, client/server AutoJumpEnabled и текущие consumer gaps Bobux собраны в [отчёте](../../../docs/ROBLOX_ORDINARY_SPAWN_RU.md). Отдельный стенд; текущие native captures не изменяют production runtime.

Текущая версия — **v2**. Замороженная v1 не запускалась и имеет INVALID_SOURCE_FIXTURE: review обнаружил потерю успешных boolean false в `and/or` serializer и недостаточную проверку server barrier. v1 сохранена отдельно, не исправляется задним числом. v2 использует explicit if/else и выполняемый official Luau CLI serializer test false/true/0/nil/error; server barrier требует все пять точек, а согласованность generation/current Character проверяет на +3s. Immediate отсутствие компонентов остаётся допустимым наблюдением.

Первый slice использует только публичный `Player:LoadCharacterAsync()`. Путь `LoadCharacterWithHumanoidDescriptionAsync` остаётся отдельным продолжением исходного плана. Нельзя считать этот slice завершением A2 или всей матрицы плана.

`build_place.py` создаёт новые XML places с девятью default inheritance fields, оставленными неуказанными, либо девятью altered values, заданными **в XML до Player join**. В обоих профилях фиксированы LoadCharacterAppearance=false, LuaCharacterController=Legacy и Players.CharacterAutoLoads=false. Последнее позволяет подписать обе стороны на CharacterAdded до первого контролируемого native load. Это явно ordinary native API path с управляемой загрузкой, а не утверждение о сроках автоматического default spawn.

Нет StarterCharacter, StarterHumanoid, custom Model, присваивания Player.Character, Humanoid.RigType или копирования полей в Player/Humanoid. Никаких скрытых Avatar/rig settings. Requested R6/R15 в имени и config — только coverage label. Нужный риг можно выбрать только штатной доступной Avatar-настройкой отдельного места **до Play**; если это невозможно либо фактический Humanoid.RigType отличается, соответствующий case сохраняется BLOCKED. Не заменять его кастомной моделью и не менять настройки опубликованной игры.

Создаются 20 session files: 2 requested rigs × 2 prejoin profiles × 5 независимых Play sessions. Train Play 1–3, holdout 4–5. Каждый файл требуется открыть в отдельной Play-сессии; повторные Character внутри одного Play не засчитываются как новые joins. Пять начальных native loads дают initial join Character и четыре respawn. Затем сервер записывает живые Player/Character, меняет **только StarterPlayer** на заранее объявленный второй probe-набор и делает ещё пять native loads. Это измеряет отдельно join-time Player defaults, будущие Humanoid и живой Character после изменения StarterPlayer. Второй probe-набор не называется «native defaults».

Для каждой генерации сервер и клиент независимо снимают CharacterAdded immediate, первый PostSimulation, +0.25, +1, +3 wall seconds. Реальное время `os.clock` сохранено; requested delay не выдаётся за точную длительность физического шага. Immediate может не содержать Humanoid: это наблюдение отсутствия в данный момент, а не искусственное ожидание готовой модели. Сохраняются milestones Humanoid/HRP/Animator/Animate, actual RigType, названия/классы/число частей и joints, scalar properties и порядок lifecycle событий. Stock scripts остаются установленными; читаются только их имена/класс/Enabled/Disabled/RunContext. Source, AnimationId/TextureId/SoundId и позы суставов не читаются.

CharacterAppearanceLoaded при LoadCharacterAppearance=false может не появиться. Фактическое отсутствие события записывается, но не автоматически объявляется дефектом. AvatarJointUpgrade/ClassicDeath имеют NOT_OBSERVABLE: скрытые rollout settings не опрашиваются. Поздняя подписка server probe на уже существующий Player отмечает отсутствие initial PlayerAdded timing и блокирует соответствующее полное наблюдение.

```powershell
python tools/roblox_character_experiments/ordinary_spawn/build_place.py
python -m unittest discover -s tools/roblox_character_experiments/ordinary_spawn -p test_fixture.py -v
```

Builder отказывается перезаписывать output directory, замораживает source hashes/fields/cases/tolerances до первого native capture и компилирует свои Luau probes официальным локальным CLI. Успех этих команд — только static/source-ready результат. Godot и Studio Play здесь не запускаются.

Команды выше описывают создание **нового** набора. Использованный v2 registration и его measured places остаются замороженными, пересобирать их для существующих captures нельзя. Trusted analyses и raw находятся в `tests/roblox_humanoid/phase_a/ordinary_spawn_v2/`; aggregate `2026-10-16-coverage-r15-both-profiles.json` подтверждает 10/20 independent joins и сохраняет общий неполный статус из-за отсутствующего R6. Description path не входит в эти 20 cases и остаётся отдельным продолжением.

Repo-owned byte-exact исходники всех **20 preregistered XML places**, `registration.json` и `places_manifest.json` сохранены в [frozen_v2](frozen_v2/). Их bytes соответствуют первоначальному manifest; frozen registration сохраняет исторический SOURCE_READY/PREREGISTERED статус до captures. Он не переписывается при появлении OBSERVED результатов. Для нового Play скопировать выбранный frozen XML в **новую рабочую папку**, открывать эту копию в Studio, а frozen оригинал не пересохранять. Настройка другого fixture или изменение измерительного кода требует новой регистрации, не изменения этих файлов.

После завершения в клиенте появится `CHARACTER_EXPERIMENT_DONE`. До Stop экспортировать **существующим** `tools/roblox_character_experiments/export_zstd.commandbar.luau` из client Command Bar. Он читает только готовую собственную папку CharacterExperimentTelemetry. Затем использовать существующий `parse_compressed_output.py` с новым output stem; исходники parser не менять. Его generic climbing baseline_summary для этого режима не является A2 анализом и не используется. Проверять raw/nested server rows, config, actual rig, generation и полноту snapshot points; все initial joins агрегировать по разным run IDs/session files.

Если клиентский probe не запустился, сервер сохраняет собственную OrdinarySpawnServerTelemetry с тем же chunk protocol. Для server-only fallback разрешено в собственной копии export helper заменить только имя папки; paired client coverage остаётся BLOCKED. Watchdog native load — 20 s, общий server/client предел — 300 s; таймаут не вызывает повторение measured case или переход к следующему load. Частичный результат сохраняется. Экспортировать каждый Play отдельно; не объединять две Studio versions или изменённый fixture под одной регистрацией.
